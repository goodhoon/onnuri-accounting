# 오클랜드 온누리교회 회계 — Day 1~3

Next.js + Supabase 기반 회계 앱의 개발 중인 소스입니다.
Day 1·Day 2는 사용자가 실제 Vercel 환경에서 로그인·회계연도·예산 저장/조회를 확인했습니다.
Day 3은 소스·SQL·자동 테스트와 빌드를 완료했으며 실제 환경 적용과 파일 전송 확인이 필요합니다.

## 현재 기능

- 이메일·비밀번호 로그인/로그아웃, 활성 계정 검사, 관리자 및 조직별 역할 관리
- 교회 → 본부 → 분과 → 팀: 초기 조직 37개, 이름 변경·조직 추가
- 기본 결재선 신청자 → 팀장 → 부서장 → 비전위원 → 지급 담당자
- 결재선 단계 이름·순서·추가·삭제와 과거 버전 보존
- 회계연도·회계계정·행사·예산 등록, 예산 증감/이동/이력과 조직별 합계
- 지출결의서 임시저장·수정·조회, 비공개 영수증 첨부/다운로드/삭제
- 제출 시 담당자와 결재선 고정, 예산 예약, 제출 철회·작성 취소와 처리 이력
- 실제 승인·반려·재신청·알림·지급은 다음 개발 범위

## 기존 Day 2 사용자의 업데이트

**DAY3_UPDATE.md**를 따라 추가 SQL 005만 먼저 실행한 뒤 소스를 업데이트합니다.
기존 001~004나 bootstrap-admin을 다시 실행하지 않습니다.

## 새 환경 설치

Node.js 22.13 이상, npm이 필요합니다. 개발 검증 환경은 Node.js 24.22.1입니다.

1. Supabase에서 공개 가입을 비활성화하고 관리자 관리 방식으로 계정을 생성합니다.
2. `supabase/migrations/`의 SQL 001~005를 파일명 순서대로 각각 한 번만 실행합니다.
3. Supabase Authentication에서 초기 사용자 계정을 만든 뒤 `supabase/bootstrap-admin.sql`의 이메일을 바꿔 실행합니다.
4. `npm ci`를 실행하고 `.env.example`을 `.env.local`로 복사해 두 변수를 설정합니다.
5. `npm run dev`로 실행합니다. 배포는 GitHub → Vercel을 사용하며 Vercel에도 동일한 두 변수를 설정합니다.

```dotenv
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
```

service_role/secret key와 비밀번호를 소스·NEXT_PUBLIC 변수·대화에 넣지 않습니다.
환경 변수가 없으면 연결 준비 화면을 표시하며, 우회 로그인이나 가상 관리자 기능은 없습니다.

## 관리 기준

- 조직·행사 코드는 3자리, 회계계정은 분류 2자리+항목 순번 2자리입니다.
- 현재 계정은 수입 4번대·지출 5번대이며 30개 항목은 분류 초안입니다.
- 이미 만든 계정 코드는 재사용하지 않습니다. 현재 화면은 추가·이름 변경·사용 중지만 제공합니다.
- 조직도 사진의 개인 이름을 계정이나 권한으로 자동 생성하지 않았습니다.
- 원자료의 회계기간·예산 금액을 자동으로 확정하거나 가져오지 않았습니다.

## 예산과 신청

금액 단위는 NZD입니다. 각 조직의 예산은 직접 보유한 배정액이며 상위 조직의 별도 한도 개념이 아닙니다.
교회 예산을 팀에 나눌 때는 예산 이동으로 보내는 쪽을 차감하고 받는 쪽에 더합니다.
상위 합계와 하위 합계를 다시 더하지 않습니다.

신청서 한 건은 예산 항목 한 개를 사용합니다. 임시저장은 예약하지 않고 제출 시 신청액을 예약합니다.
영수증과 실제 조직별 역할이 있는 결재 담당자가 필요하며 본인은 담당자로 지정할 수 없습니다.
제출 후 내용/첨부는 잠기고 철회 시 예약을 해제합니다. 취소·철회 기록은 보존합니다.
예산 예약은 실제 승인·지급 완료를 의미하지 않습니다.

## 파일 보관

SQL 005가 private `expense-receipts` 버킷과 RLS를 생성합니다.
JPG/PNG/PDF, 파일당 5MB, 건당 10개이며 영구 공개 링크를 사용하지 않습니다.
업로드는 브라우저에서 Storage로 직접 보내고 다운로드는 권한 검사 후 짧은 유효시간의 링크를 발급합니다.
새 사용자에게 Storage 전체 접근이나 service_role 키를 주지 않습니다.
